# 修复容器外拖拽落点不一致

## Goal

确保项目详情页拖拽任务时，最终实际落点始终与释放鼠标前显示的落点预览一致，包括指针超出任务容器后仍显示最后有效预览的场景。

## Background

- 项目详情页的任务分组拖拽由 `ProjectTaskLayout` 管理，拖动期间通过本地布局和任务占位符展示预览，成功放置后才提交完整布局。
- 任务碰撞检测在指针未命中任务、分组标题或任务容器时返回空目标（`packages/frontend/src/components/project/ProjectTaskLayout.tsx:443`）。
- 当前 `handleDragOver` 收到空目标时保留最后一次有效悬停生成的占位预览（`packages/frontend/src/components/project/ProjectTaskLayout.tsx:507`）。
- 当前 `handleDragEnd` 在空目标上释放时却恢复拖拽开始前的布局且不持久化（`packages/frontend/src/components/project/ProjectTaskLayout.tsx:525`）。因此释放前看到的是最后有效落点，释放后任务却回到原位。
- 用户已明确选择粘性落点语义：指针超出容器后若仍显示最后一个有效落点预览，释放时应在该预览位置完成放置。
- 现有测试只覆盖“容器外释放后恢复”，与确认后的产品语义相反（`packages/frontend/src/components/project/ProjectTaskLayout.test.tsx:646`）。

## Requirements

### R1 — 最后有效预览决定实际落点

- 任务拖动过程中，指针离开所有有效放置目标后，继续保留最后一个有效落点预览。
- 若在容器外释放鼠标，最终布局必须与释放前显示的预览一致。
- 若该预览相对拖拽开始布局有变化，只提交一次完整布局重排 mutation。
- 若拖拽期间从未形成有效的新落点，或最后预览与开始布局相同，则不提交 mutation。

### R2 — 拖拽会话行为

- 浮动任务条目在容器外继续跟随指针，拖拽会话保持有效。
- 指针重新进入任一有效任务、分组标题或任务容器后，使用新目标更新插入预览；随后无论在目标内还是再次移出后释放，实际落点都采用最后显示的预览。
- Escape/拖拽取消必须继续恢复拖拽开始布局且不提交 mutation；取消语义不受粘性落点影响。

### R3 — 回归保护

- 保持现有任务同组排序、跨组移动、分组标题首位插入、容器末尾插入、键盘拖拽和分组排序行为。
- 保持无变化放置不提交重排请求，保存失败仍恢复服务端布局并显示既有错误提示。
- 变更仅限项目详情页的任务分组拖拽，不改变侧边栏、通用任务列表、已完成任务区、后端接口或 DTO。

## Acceptance Criteria

- [ ] AC1 (R1): 任务预览到新位置后把指针移出所有有效目标，最后有效占位预览保持可见。
- [ ] AC2 (R1): 在容器外释放后，任务实际位置与最后有效预览一致，并且完整布局 mutation 恰好调用 1 次。
- [ ] AC3 (R1): 未形成新落点或最后预览无变化时在容器外释放，mutation 调用次数为 0。
- [ ] AC4 (R2): 指针移出后重新进入另一有效目标，预览更新到新目标；再次移出并释放时，提交布局与该新预览一致。
- [ ] AC5 (R2): Escape 取消始终恢复拖拽开始布局且 mutation 调用次数为 0。
- [ ] AC6 (R3): 任务同组/跨组拖动、有效目标内释放、键盘拖拽、分组排序及保存失败恢复相关测试继续通过。
- [ ] AC7: `ProjectTaskLayout` 聚焦测试、前端 typecheck、lint 和完整测试套件通过。

## Out of Scope

- 鼠标离开有效目标时撤销最后落点预览或将容器外释放视为取消。
- 引入新的最近目标吸附算法或视觉样式。
- 修改碰撞算法的有效目标优先级、拖拽激活距离或自动滚动策略。
- 修改后端、共享 DTO、API、缓存或 i18n。

## Risks and Deferred Items

- 当前前端规格记录了“容器外释放即取消”，与用户确认的粘性落点语义冲突；实现验证后必须同步更新该规格。
- 容器外提交只能使用当前已渲染的最后有效预览，不能重新用空碰撞目标计算落点，否则会再次产生不一致。
- 必须继续区分鼠标在容器外释放与 Escape/系统取消，避免取消操作意外持久化。
