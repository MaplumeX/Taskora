# Hide add-subtask button when subtasks exist

## Goal

让任务展开行底部图标栏的"添加子任务"按钮回归其语义：仅作为"创建第一个子任务"的入口，而非子任务区块的折叠开关。

## Background

当前 `TaskRowExpanded.tsx` 底部的 `ListPlus` 按钮 aria-label 为"添加子任务"，但实际绑定的是 `toggleSubtasksOpen()`——切换子任务区块的展开/折叠。这造成两个问题：

1. 按钮名不副实：叫"添加子任务"却干着折叠面板的活。
2. 即使已经有子任务，该按钮仍一直显示，与子任务区块内的输入框功能重叠。

## Requirements

- 没有子任务时：显示该按钮，点击后展开子任务区块并聚焦输入框（用于创建第一个子任务）。
- 已经有子任务时：不再显示该按钮（子任务区块默认展开，区块内已有输入框可继续添加）。
- 该按钮不再承担"折叠/收起"子任务区块的职责。

## Out of Scope

- 子任务区块内部已有行为的改动（列表展示、输入框、完成/删除等）。
- 其它图标按钮（日程、截止、项目、区域、标签）。
- i18n 文案的新增或改动。

## Acceptance Criteria

- [ ] 任务无子任务时，底部图标栏显示"添加子任务"按钮；点击后子任务区块展开且输入框自动聚焦。
- [ ] 任务有子任务时，底部图标栏不显示"添加子task"按钮。
- [ ] 子任务区块在有子任务时默认展开；在无子任务且未点击按钮时默认不显示。
- [ ] 现有相关测试通过或被同步更新以反映新行为。
