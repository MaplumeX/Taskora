# 重新设计任务编辑组件布局

## Goal

重新设计任务展开编辑态（`TaskRowExpanded`）的布局，使其看起来是"一体的、直接展开"的编辑体验：从上到下依次为标题、备注、子任务区、图标按钮行。

## Current State

`TaskRowExpanded.tsx` 当展开态时，从上到下为：
1. 顶部一行：左侧"标记完成/取消完成"文字按钮 + 右侧一排图标按钮（日期、到期、项目、区域、标签、删除）+ 删除图标按钮
2. 标题输入框
3. 备注文本域
4. 分隔线
5. 子任务区（标题 + 列表 + 添加输入框）

## Requirements

1. **新的展开编辑态布局**，从上到下依次：
   - ① 标题（可编辑输入框，带边框以示"进入编辑状态"）
   - ② 备注（文本域）
   - ③ 子任务区（标题 + 子任务列表 + 添加子任务输入框）
   - ④ 图标按钮行（仅保留：日期、到期、项目、区域、标签）

2. **移除项**：
   - 移除展开态中的"标记完成/取消完成"文字按钮（折叠态行的勾选框已提供完成入口）
   - 移除展开态中的"删除"图标按钮（删除入口保留在折叠态行 hover 显示，即 `TaskItem.tsx` 中 `!expanded` 分支已有）

3. **保留项**：
   - 折叠态行（`TaskItem.tsx`）的字段展示（标签点、项目/区域标题、日期 badge、到期 badge）不变
   - 折叠态行 hover 时显示的删除按钮不变
   - 折叠态行点击展开/折叠交互不变
   - 所有图标按钮（日期、到期、项目、区域、标签）的原有 Popover 功能和交互不变
   - 标题、备注的编辑/提交（onBlur commit）行为不变
   - 子任务列表、添加子任务的交互不变
   - 通过 add task 流程展开并自动聚焦/选中标题的逻辑不变

4. **视觉对齐**：
   - 标题、备注、子任务区、图标按钮行整体视觉上"一体"，过渡自然
   - 图标按钮行移到最底部后，仍保持左对齐或右对齐中更合适的一种（实现时取视觉更优）

## Out of Scope

- 不修改后端接口或 DTO
- 不修改折叠态行 `TaskItem.tsx` 的非删除按钮相关布局
- 不新增字段或功能

## Acceptance Criteria

- [ ] 展开编辑态从上到下依次为：标题、备注、子任务区、图标按钮行（仅 5 个图标）
- [ ] 不再有"标记完成/取消完成"文字按钮
- [ ] 不再有展开态内的删除图标按钮；折叠态 hover 删除按钮仍可用
- [ ] 所有图标按钮的 Popover（日期/到期/项目/区域/标签）功能正常
- [ ] 标题、备注的编辑与提交（onBlur commit）行为正常
- [ ] 子任务列表展示、添加子任务功能正常
- [ ] add task 流程展开后自动聚焦并选中"新任务"标题的逻辑仍正常
- [ ] 折叠态行的字段展示（标签点、项目/区域、日期 badge、到期 badge）不变

## Notes

- 这是一个中等复杂度的前端 UI 重构任务，限定在 `TaskRowExpanded.tsx`（主要为该文件内部布局重排和移除部分 JSX）。
- 是否需要 `design.md` / `implement.md` 取决于实现时是否需要技术设计决策；本任务基本为 JSX 重排，若实现直白可保持 PRD-only。
