# 01：共用草稿落库、补发队列、失败通知

Status: implemented — awaiting device verification

## Problem

桌面和 Android 的 Quick Add 都要从「只有标题」升级为完整草稿。如果各写一套转换和校验规则，迟早会分叉。同时，Android 现有的冷启动补发只存一条，落库失败也会被静默吞掉。

## Design

见 spec 第 4、5 节。

- `packages/api` 新增 `QuickAddDraft` 和 `createFromQuickAddDraft`，负责转换 DTO、create、补写 Reminder、校验并回落，返回 `{ taskId, placedIn }`。
  - Someday 的写法与主应用里「设为 Someday」保持一致，实现时先确认 `bucket` / `scheduledType` 的取值。
  - 校验用的 Tag、Project、Area 数据从本地副本读取。
- 新增 `parseQuickAddInput(input)`：`input` 是 JSON 时解析为草稿；否则当作纯标题；格式不合法时也退回为纯标题。
- `status-bar/controller.ts`：`createTask(title)` 选项改为 `createDraft(draft)`；失败时调用新增的 shell 方法 `notifyQuickAddFailed(title)`，不再吞掉错误。
- `StatusBarPlugin.kt`：`PENDING_QUICK_ADD_KEY` 从单个字符串改为 JSON 数组；`submitQuickAdd` 往数组末尾追加，由 JS 取走（见 Comments）。读到旧版本留下的单个字符串时，当作一条处理。
- 失败通知使用独立的通知渠道 id，点击打开 App。

## Acceptance

- 进程未起时连续添加 3 条，App 启动后 3 条都在，顺序正确。
- 草稿引用了已删除的 Tag 或项目时：Tag 被丢弃，任务落入 Inbox，不报错。
- 断开 Engine 或模拟写入失败时，出现失败通知。
- 测试：
  - `createFromQuickAddDraft` 单测，覆盖各字段、Reminder 二次写、回落；
  - `controller.test.ts` 覆盖 JSON 与纯文本两种输入，以及失败通知。

## Comments

### 2026-10-02：实现

- `packages/api/src/quick-add/draft.ts`：`QuickAddDraft`、`parseQuickAddInput`、`createFromQuickAddDraft`（依赖可注入，便于测试）。
  - Someday 写 `scheduledType: SOMEDAY`，Bucket 由 `planTaskCreate` 推导，不在草稿层指定。
  - 项目只接受未进回收站且状态为 ACTIVE 的；已完成的项目同样回落 Inbox。同时带 `projectId` 和 `areaId` 时以项目为准。
  - 非法字段逐个丢弃，不整条拒绝；JSON 损坏或缺标题时，整串当作标题。
- 控制器：`createTask(title)` 改为 `createDraft(draft)`；失败时调用 `shell.notifyQuickAddFailed`，之后照常刷新常驻通知。
- **补发通路改为「取走」模式**（与 reminders 插件的 `takePendingActions` 相同）。原来的写法是在插件 `load` 时直接 `trigger('action')`，但那时 JS 还没注册监听（`takeNavigation` 的注释也写明了这一点），冷启动补发的那条很可能丢失。现在：
  - 浮层提交一律入队，再发 `quick-add-available` 信号；
  - JS 注册监听后先 `take_pending_quick_adds` 一次，之后每次收到信号再取；
  - 原生取出即删，重复取只会得到空列表。
- 浮层提交的格式已改为 `{"title": ...}` JSON，为 03 的字段做好准备。
- 新增插件命令 `take_pending_quick_adds`、`notify_quick_add_failed`（Rust、build.rs、default.toml；autogenerated 权限文件由 `cargo check` 重新生成）。失败通知使用独立的 DEFAULT 渠道 `quick-add-failed`。
- 测试：`draft.test.ts`（10 条）、`controller.test.ts`（新增草稿 JSON 和失败通知两条）、`tauri-shell.test.ts`（队列取走、失败通知）。
- **未验证**：本环境没有 Android SDK，Kotlin 部分没有编译过，冷启动 / 热启动补发和失败通知都需要真机验证。
