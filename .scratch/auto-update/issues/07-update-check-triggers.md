# 缩短更新检查周期并补齐事件触发

Status: resolved

## 内容

- 每小时检查所连 Sync Hub 的版本，避免普通兼容升级要等一天才被发现。
- 切换服务器立即检查；回前台 / 恢复网络按 5 分钟节流检查。
- 已准备好的安装包在同一平台壳内复用；未发布的安装包下次重试。
- 自动检查关闭时所有自动触发都停止，手动检查仍可用。

## 实现

- `api/client.ts` 提供服务器地址变更订阅，仅实际变更才通知。
- `update-checker.ts` 装配并清理定时器、地址订阅与前台 / 网络监听；失败尝试也参与前台节流。
- `/health` 请求使用当前地址快照与 15 秒超时；切换后旧检查的成功、失败与下载结果不写入当前结论。
- 切换时串行等待旧准备流程结束再查新服务器，避免原生壳的待安装版本被并发下载覆盖；停止后取消等待中的自动检查。

## 验收

- 更新检查、版本判定和 API client 的 55 项测试通过，覆盖小时检查、事件节流、关闭与停止、服务器切换和下载竞态、安装包复用与重试。
- 原生下载安装的真机验收仍由 issue 05 / 06 跟踪。
