# New in Today 确认横幅与单条已读

参考 Things 3 实机行为：新到条目不再自成一区，留在原有排序位置与分组里，仅行首带黄点；Today 标题（日期）下方出现黄色横幅「你有 X 个新的待办事项」，最右按钮「好」。黄点按常见的「新东西」模式处理：单条交互清掉该条，「好」清掉全部。

## 判定

新到判定规则不变（计划日期晚于已确认日期，且排期发生在计划日期之前；写入时刻未知只按前一条），再排除单条已读集合中的条目。仍为纯推导，不改写 Task / Project 字段。

## 状态

- `todayReviewedOn` 语义改为「已确认日期」：只在点「好」或单条已读清空全部新到时推进到今天；进入 / 离开 Today 不再推进。只进不退，经账号偏好跨端同步。从未确认过时不标新到。
- 账号偏好新增单条已读集合，元素为 `task:<id>@<计划日期>` / `project:<id>@<计划日期>`。带计划日期，同一条目日后改期再次随日期到来时重新算新到。
- 推进已确认日期时清空集合；剩余新到逐条读完（X 归零）时等同点「好」。
- 偏好整体覆盖写入，两端并发标记已读可能丢一条，结果仅是该条黄点重现，接受。
- 写回失败保留本地状态，下次再写（沿用现有 `markTodayReviewed` 做法）。基线改为订阅 store，其他设备确认后本端即时消失。

## 单条已读触发

清除：展开 / 打开详情（任务展开、进入项目页）；编辑任何字段（标题、备注、日期、标签等）；拖拽排序。
完成 / 取消 / 删除：条目离开 Today，自然消失。
不清除：单击选中、多选、悬停。

## 横幅

- 位于 Today 页日期下方、标签筛选与列表之上；黄色背景（`today` 色系），左侧文案，最右「好」。
- X 为全部未读新到条目数（任务与独立项目行），不受标签筛选影响；X 为 0 不显示。
- 桌面、网页、手机共用。

## 入口黄点

侧边栏 / 手机首页 Today 入口黄点持续到全部新到已读或已确认。

## 移除

- `GroupedFeedListView` 的 `FRESH` 容器、新到区置顶及「仅可区内重排」的拖拽限制；改为按新到键集合给行加黄点。
- `useNewInTodayKeys` 中进入 / 离开自动推进的逻辑与进入时基线快照。

## 文档

更新 `CONTEXT.md` New in Today 词条：去掉「在 Today 顶部自成一区……仅可区内重排」与「进入 Today 即把已看日期推进到今天（本次访问内黄点保留，离开后消失）」，改述横幅确认与单条已读。Review 词条中对 `todayReviewedOn` 的说明同步改为「已确认」。
