# 03: 点击状态栏常驻通知跳转到今天

Status: resolved

## 问题

点击状态栏常驻通知本体只会把 App 带回前台，停在**上次所在的界面**；
窄屏冷启动走 `/` → `RootRedirect` → `/home`，并非用户期望的 Today。

## 根因

- `StatusBarService.buildNotification` 的 `contentIntent` 用
  `PackageManager.getLaunchIntentForPackage()`，是纯启动意图，不携带
  任何路由信息。
- mobile 用 `BrowserRouter`（真实 URL），App 存活返回前台时 webview
  URL 仍是上次路由；冷启动则落到 `/home`。两种路径都到不了 `/today`。

## 修复范围

沿用仓库现有的「平台壳投递请求 → Router 内消费」模式
（`taskReveal.store` + `useTaskRevealListener`）：

- **原生**（`tauri-plugin-statusbar`）
  - `contentIntent` 的 launch intent 加 `EXTRA_NAVIGATE = "today"`；
  - 冷启动：`StatusBarPlugin.load()` 读取 `activity.intent` 的 extra，
    存进插件实例，由 `takeNavigation` 命令取出（取出即删）；
  - 热启动（MainActivity 为 `singleTask`，Tauri 模板如此）：覆写
    `onNewIntent(intent)`，读取 extra 后 `trigger("navigate")` 事件；
  - `readNavigation` 读完 `removeExtra`，避免 Activity 重建时重复导航。
- **Rust**：`take_navigation` 命令转发 `takeNavigation`，返回
  `Option<String>`；`build.rs` 的 `COMMANDS` 与权限声明同步更新
  （`allow-take-navigation`），避免重蹈 issue 01 的 ACL 覆辙。
- **JS 壳**（mobile）：`takeStatusBarNavigation()`（冷启动主动取）与
  `onStatusBarNavigate()`（热启动事件订阅，映射 `destination === 'today'`）。
- **JS 装配**：`initStatusBar()` 两条路径统一
  `requestNavigation('/today')`——请求可能早于 Router 挂载，故以待处理
  状态保存。
- **API / UI**：新增 `navigationRequest.store` 与
  `useNavigationRequestListener`，在 `AppShell` 内消费并 `navigate(path)`，
  与 `useTaskRevealListener` 并列。

导航语义独立于平台无关的 `StatusBarController`（只关心轮播/快速添加），
因此不复用 controller 的 `tap` 动作，而是在壳层与 AppShell 之间走
store，平台无关包不感知 Android。

## 验证

- API 全量 355/355、UI 全量 497/497、Mobile 全量 75/75 通过；新增
  `useNavigationRequest.test.tsx`（冷启动早于挂载、挂载后投递）与
  mobile 壳的 take/navigate 转发测试。
- API / UI / Mobile `tsc --noEmit` 通过；改动文件 ESLint 通过。
- `cargo check`（host）与 `cargo check --target aarch64-linux-android`
  均通过（`statusbar` 插件与 `taskora-mobile` 应用 crate）。
- 权限文件经 `tauri_plugin::Builder` 重新生成（reference.md、schema.json、
  autogenerated/commands/take_navigation.toml）。

## 未验证（需 Android SDK / 真机，本机不具备）

- Kotlin 编译与 `tauri android init` 的 gradle include；
- 真机：点通知冷启动落 Today、App 存活时点通知切到 Today、返回手势
  可回到进入前界面、Activity 重建不重复导航。

## 已知边界

- 已在 `/today` 时点通知会再 push 一条历史记录（与 Reveal Task 的
  `navigate` 行为一致），返回需多按一次；未做去重。
- 冷启动的 extra 依赖 Android 用通知意图重建/投递 MainActivity；若
  厂商 ROM 有额外拦截，属平台行为。
