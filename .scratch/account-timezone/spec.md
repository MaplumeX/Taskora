# 日历日期与账号时区

Status: resolved

## 顺序与验收

1. 修复「计划今天、每天重复、完成后下一实例仍是今天」：计划日期/截止日期按日历日期处理，不再混用本地零点 ISO 与 UTC 日。
2. 引入账号级 IANA 时区，首次默认设备时区，服务端保存并跨端读取，设置允许修改。
3. 统一依赖时区的使用点：Today/Upcoming（任务、项目、事件缓存）、日期快捷入口与日历高亮、截止倒计时、Logbook、重复完成日锚点及预览、提醒排程与文案、Android 状态栏、助手当前日期、导出文件日期。
4. 回归覆盖 UTC+8、UTC 负偏移、跨日及 DST；验证 Engine 与 REST 口径一致。

## 数据契约

- 客户端新写入的 scheduledDate/dueDate 使用 YYYY-MM-DD；后端既有 DateTime 列保留，UTC 零点仅为日历日期的存储编码，不代表用户零点。
- 兼容旧非零点 ISO 日期时，按首次账号时区（服务端管理的 legacyDateTimeZone）恢复日历日期，该值不随设置修改，防止旧日期移动；UTC 零点编码按其年月日直接读取（旧记录未存原始时区，存在无法无歧义恢复的边界）。
- createdAt/updatedAt/settledAt/trashedAt、认证有效期、同步 HLC 仍是绝对时刻，不改写。
- 日期运算保持纯函数；账号时区显式传入核心逻辑，不能读取服务器 TZ。
- 新设置沿用已有通用设置视觉和偏好管线，不引入独立布局。

## 核查结果

已统一：计划/截止日期选择和快捷按钮、Today 页标题、任务与项目 Today/Upcoming 过滤、事件缓存匹配、日历与 Upcoming 分组、Deadline 倒计时、Logbook 分组/徽标、重复规则计算和预览、提醒排程/文案/时区修改重排、Android 状态栏日期排序和前缀、助手每次对话的当前日期、导出文件名。

不修改：创建/更新/了结/删除的绝对时间戳、认证令牌过期、同步 HLC、通知系统所需 epoch ms。客户端显示这些时刻所属的日历日时才转换账号时区。

兼容说明：新写入为 YYYY-MM-DD，REST 继续用原 DateTime 列，故不需要数据库结构迁移。账号时区在登录或读取当前用户时以条件原子写初始化；每分钟及窗口聚焦时获取远端偏好。设备离线继续用已缓存偏好。旧错误算法已经生成的当天实例不会自动改到明天；原始设备时区已丢失的历史输入只能按首次账号时区解释。

## 剩余边界

- 离线设备无法即时收到账号时区修改，在重新同步偏好前仍使用上一次时区；此期间并发完成的完成日锚点仍可能不同。
- 无法自动判断或修复旧算法已经生成错误日期的实例。
- 真实数据库的初始化 SQL 与真实系统通知排程尚未做集成/真机验证。
